# Mars Notebook 改善記録

人間のプレイテストは未実施。以下は開発者の操作観察・自動ブラウザー検証・決定的なボットによる比較であり、子どもの評価を代替しない。

## 基準

- 全体調査: README / AGENTS / API資料 / domainとテスト / game全体 / CSS / 日英翻訳 / データ / package / CIを確認。
- 改善前 `npm run check` と `npm run build`: 成功。Phaserバンドルサイズ警告あり。
- 優先問題: 待機への戻し方が説明と不一致、配置の意味が見えにくい。夜に健康・収穫・発見の表示がない。ソラの配置だけで勝てる。スマホでは全体が縮小され操作が小さい。

## サイクル1: 配置の入口

問題：待機への戻し方が説明と不一致。隊員の専門や選択後の次の操作がhover頼み。
なぜ面白さを損なうのか：試行錯誤の前に操作で詰まり、得意配置の意味を発見しにくい。
改善案：待機ボタンで選択隊員を戻す。隊員に専門アイコンを添え、選択中だけ短い次操作ヒントと候補マスを示す。盤面にはキーボード操作用のボタンも用意する。
予想するプレイヤー体験の変化：選ぶ→置く→戻すを説明書なしで試せる。
検証方法：セッションテスト、ブラウザーで配置・戻す・キーボード操作を確認。
成功条件：選択隊員が1操作で待機へ戻り、配置先と専門が色以外でも分かる。非計画フェーズでは変更不可。
結果：実装済み。2026-11-14 のブラウザ検証で、ミオを置いて待機へ戻し `cell === -1`、隊員ボタンは PC 52px・スマホ 56px、日英切替とヘルプを確認。ページエラーなし。

## サイクル2: 夜の結果とフレアの収支

問題：夜に元気・収穫・発見が見えず、フレアの3択で電力と研究の得失が読み取れない。敗北理由も分からない。
なぜ面白さを損なうのか：選んだ結果が夜に消えると、次の朝の判断が勘になる。
改善案：夜レポートに元気・収穫・発見を出す。フレアは3択の収支を予報に出す。敗北モーダルに原因を出す。
予想するプレイヤー体験の変化：負けた理由と、まもる／研究を続ける差を読める。
検証方法：ブラウザで15日勝利、6日敗北、フレア画面、夜の収穫と発見。
成功条件：勝利・敗北・フレア・夜の収穫または発見が、色だけに頼らず読める。
結果：実装済み。今回の playtest で15日勝利（研究75）、水と食料切れの敗北文、夜の「収穫 +9」、研究の発見（`.discovery`）を確認。人間の子ども評価は未実施。

## サイクル3: スマホの操作サイズ

問題：スマホでは盤面ごと縮小され、操作が約18pxになる。
なぜ面白さを損なうのか：指でマスと隊員を押せない。
改善案：幅900px未満は縦の専用UIにし、主な操作を56px前後にする。
予想するプレイヤー体験の変化：スクロールしながら建設・配置・進行ができる。
検証方法：幅390で横はみ出しなし、操作矩形が44px以上。
成功条件：390pxで横スクロールが出ず、見える隊員ボタンが44px以上。
結果：playtest が390で scrollWidth と 56px を確認。成長表示の pips と `Lv.1 · 0 · 0/5` も flex で表示。

## サイクル4: 生命維持の電力

問題：ソラを実験室に1人置くだけで15日勝てる。電力のトレードオフが弱い。
なぜ面白さを損なうのか：配置を変えても勝敗が動かない。
改善案：新規基地だけ `rules_version` 4 とし、昼に生命維持電力5（ゲーム用の値）を引く。4でない保存は version 3 のまま、この消費をしない。
予想するプレイヤー体験の変化：発電を置かないと途中で電力が尽きる。
検証方法：`npm run evaluate`。変更前は `docs/strategy-baseline.json` に固定。変更後は `docs/strategy-current.json`（2026-11-14 に再実行して保存）。ボットであり人間ではない。
成功条件：ソラ1人の定常配置が15日勝利ではなくなり、発電を厚くする配置は勝つ。旧セーブの規則は変わらない。
結果（再計算、2026-11-14）：
- 変更前 stationary: 勝利、15日、研究75、残電力47。
- 変更後 stationary: 敗北、生存カウント7、研究30、電力-3、不足2回。8日目の解決で電力が尽きる。
- power: 勝利、15日、研究75、電力68。
- research: 勝利、15日、研究112、電力3、不足1回。
- safety: 勝利、15日、研究65、電力31、元気100。
- frugal: 勝利、15日、研究75、電力95。
- random 20本: 勝利13→12。平均生存はどちらも13.6。平均研究 40.15→38.25。
数値はゲーム用。NASAの実測電力ではない。

## サイクル5: モーダルのキーボード

問題：ヘルプや確認が開いても Tab が背面へ抜け、Escape とフォーカス復帰がない。
なぜ面白さを損なうのか：キーボードだとダイアログから戻れない。
改善案：開いている面で Tab を循環し、Escape で閉じ、開いたボタンへ戻す。
予想するプレイヤー体験の変化：ヘルプをキーボードだけで開閉できる。
検証方法：ブラウザでヘルプを開き、先頭と末尾の Tab、Escape、復帰先を見る。
成功条件：フォーカスがモーダル内に留まり、Escape 後に助けボタンへ戻る。
結果：playtest で達成。以前は未再検証だった。

## サイクル6: 壊れた保存

問題：夜レポートの形が壊れていると復元に失敗しうる。`storage.getItem` の失敗も落ちる。
なぜ面白さを損なうのか：続きから遊べず、最初からに戻る理由も出ない。
改善案：夜レポートを正規化し、読み書き失敗時は `saved = false` と「保存できませんでした」を出す。
予想するプレイヤー体験の変化：壊れた保存でも起動し、保存できないことが分かる。
検証方法：ブラウザで `setItem` を失敗させる、保存文字列を `{` にする、`getItem` を例外にする。
成功条件：落ちずに起動し、失敗時は保存失敗の表示が出る。壊れた夜レポートはテストで正規化される。
結果：playtest で保存失敗の表示、`{` のまま新規1日目が開くこと、`getItem` 例外でもページエラーなしを確認。`npm run check` は夜レポートの正規化テストを含む。

## サイクル7: 成長の見える化

問題：施設レベルは盤面の小さい文字だけで、収穫までの進みと収穫した夜のマスが弱い。スマホのマスは名前と人だけ。
なぜ面白さを損なうのか：改良とプラントの5稼働日が結果の夜まで見えず、強くした実感が残らない。
改善案：既存の level / progress / harvest_cells だけを使う。PC盤面は塗りつぶしの段数、Lv の数字、温室の枠付き進捗と分数、収穫夜は枠と★。スマホのマスは同じ段数、`Lv.n · 人数 · 進捗/日数`。新しい規則と依存は足さない。domain は変えない。
予想するプレイヤー体験の変化：改良した居住区と、収穫したプラントを朝を待たずに指させる。
検証方法：ブラウザで居住区を改良し data-level が2、温室の短文、収穫夜の class と夜の収穫文。幅390で段数と短文が見える。
成功条件：レベルが数字と塗った段の両方で分かり、温室は分数があり、収穫したマスは枠以外に★がある。
結果：達成。居住区は Lv.2 と塗った段。収穫夜の画面に枠、★、`収穫 +9`、リセット後の `0/5`。390px のスクリーンショットで `Lv.1 · 0 · 0/5` と段を確認。色だけにはしていない。

7テーマで、操作・夜の結果・スマホ・電力の差・キーボード・保存・成長表示は一通り見える。

## サイクル8: 昼の空操作

問題：昼に判断もイベントもなく、毎日「結果」が必要で、15日で進行クリックが約45回になる。
なぜ面白さを損なうのか：予測も選択も増えないクリックが、朝と夜の判断の間に入る。
改善案：朝の「開始」のあと、最大450msの作業表示（reduced-motion は 0）で夜へ進む。夜の「翌朝」は手動。昼の「結果」は押すと計算へ進む。タイマーはキャンセルし、phase が昼のときだけ解決する。起動画面では進めない。昼の保存は開始後に1回だけ解決する。Session と domain の phase とセーブ形は変えない。
予想するプレイヤー体験の変化：朝の計画と夜の結果だけを押す。
検証方法：朝クリックから3秒以内に夜、夜クリックで朝。15日勝利まで進行30回。即スキップでも計算は1回。reduced-motion、昼セーブの開始後1回、夜の再読込で二重解決なし。
成功条件：上の検証が通り、既存の配置・勝敗・収穫・発見・フォーカス・保存失敗も残る。
結果：playtest が成功した。PC と390の両方で進行30回のあと15日勝利し、6日敗北も通った。手動の「結果」、起動画面中は昼のまま、開始後の1回だけ夜へ進むこと、夜の再読込、reduced-motion でも日次の数値が二重に変わらなかった。

保存失敗の表示は、スマホのヘッダーで幅を取りタイトルが縦につぶれていた。`.save-failed` を幅100%の独立行にし、タイトルに min-width を付けた。`screenshots/current-390-save-title.png` で「火星基地」が横に読める。モバイルの人数は `0/2` のように定員付きにした。

8サイクルで今回の改善は終える。人間と子どものプレイテストは未実施。追加の施設やイベントは、その観察がないので増やさない。
